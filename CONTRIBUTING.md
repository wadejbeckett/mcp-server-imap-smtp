# Contributing

Contributions are welcome: bug reports, fixes, documentation and support for more mail server set-ups.

- **Before you start.** Open an issue first for anything larger than a small fix, so the approach can be agreed.
- **Set up.** `uv venv && uv pip install -e ".[dev]"`, then `.venv/bin/pytest`. Every change needs tests, and the suite must pass. Integration tests against a real mailbox are opt-in: `pytest -m integration`, with credentials from the environment (see docs/RUNNING.md).
- **Test lab.** `scripts/lab.sh up` starts three local mail servers in Docker (Dovecot 2.4 with Pigeonhole, and Postfix, from Debian's packages; the image is built from `lab/`), then `.venv/bin/pytest -m lab` runs the lab tests against them; `scripts/lab.sh down` removes the containers and their mail. Each profile listens on 127.0.0.1 only: `flat` (folders beside INBOX, every extension) on 10993 (IMAPS), 10465 (SMTPS), 10587 (submission, STARTTLS required) and 10190 (ManageSieve); `prefixed` (every folder under `INBOX.`) on 11xxx; `stripped` (flat, without MOVE, UIDPLUS or ESEARCH, for the fallback paths) on 12xxx. The first `up` makes a private CA and a `localhost` certificate in `lab/.state/` (not committed); the tests trust only that CA. The fixture mailboxes `alice@example.test`, `bob@example.test` and `carol@example.org` and their lab-only passwords are in `lab/dovecot/users`; `sales@example.test` is an identity only alice may send as. The servers have quota, ACL, METADATA, special-use folders and Sieve (vacation, fileinto, imap4flags, variables); submission enforces SIZE (25 MB), DSN, CHUNKING, SMTPUTF8 and that the envelope sender belongs to the signed-in mailbox. New tests that need a server should target the lab (helpers in `tests/_lab.py`) rather than a real mailbox.
- **Style.** Keep the style of the surrounding code: small functions, plain names, and comments that explain why rather than what.
- **Security.** The connector holds other people's mail passwords. Changes to sign-in, sealing, tokens or the mail server binding get extra review. Never log message content, recipients, tokens or passwords.
- **No company specifics in the code.** Operator names, hosts and limits belong in the configuration.
